# Промпты для Claude Code

Запускайте Claude Code из корня проекта (`cd support-agent-eval && claude`). Он читает CLAUDE.md сам.

## Может ли Claude Code "следить" за папкой?
Нет, фонового наблюдения за файлами у него нет. Он работает, когда вы даёте задачу: читает и правит файлы внутри папки запуска (с вашего разрешения на каждое действие, либо режим авто-принятия правок). Для автоматики:
- Разовый запуск без диалога: `claude -p "ваша задача"`
- Автопрогон метрик при изменении промпта делает не Claude, а обычная утилита: `ls prompts/*.txt | entr -c sh -c 'python src/run_agent.py --prompt prompts/prompt_v2.txt && echo done'` (entr: `brew install entr` / `apt install entr`)
- Хуки Claude Code (settings) могут запускать команду после его правок, например тесты.

## Промпт 1. Проверка окружения
```
Прочитай CLAUDE.md и docs/labeling_guidelines.md. Создай .venv, установи requirements.txt,
проверь что `python src/make_candidates.py --per-category 10` работает. Ничего не меняй в data/golden.csv.
Покажи 5 первых строк data/candidates.csv и распределение bitext_category.
```

## Промпт 2. Кандидаты из датасета
```
Запусти src/make_candidates.py с --per-category 10. Проверь в data/candidates.csv: нет ли дублей текстов,
пустых строк, слишком коротких (<4 слов) и слишком длинных (>60 слов) текстов. Выведи список подозрительных id.
Не удаляй строки, только покажи отчёт.
```

## Промпт 3. Сложные случаи для golden set (черновики, их разметит человек)
```
Прочитай docs/labeling_guidelines.md. Сгенерируй 50 коротких обращений клиентов интернет-магазина на английском
и сохрани в data/hard_cases_draft.csv с колонками: id (h001...), text, source (=llm_draft), type, comment.
Состав: 12 edge (две темы в одном сообщении, двусмысленные), 14 rare (мошенничество, юридические угрозы,
просьба человека, угроза безопасности; разной формулировки, не копируй слова из инструкции),
14 negative (очень эмоциональные или грубые, но escalate=false по правилам), 10 noisy (опечатки, пустое, мусор, смесь языков).
НЕ заполняй category и escalate. Тексты должны звучать как реальные люди: разная длина, стиль, без шаблонных фраз.
```

## Промпт 4. Ваша разметка и сравнение с подсказкой (после того как разметили сами)
```
Я разметил data/golden.csv вручную. Прочитай docs/labeling_guidelines.md и для каждой строки предложи свою метку
в новом файле data/ai_second_opinion.csv (id, ai_category, ai_escalate, ai_reason одной фразой).
data/golden.csv не меняй. Затем покажи таблицу строк, где мои метки и твои расходятся, и для каждой скажи,
что в инструкции неоднозначно. Это материал для уточнения инструкции, а не для автоматической замены моих меток.
```
Зачем так: если сначала смотреть подсказку модели, вы заякоритесь на ней, а потом модель оценивается по её же меткам (круговая оценка).

## Промпт 5. Прогон и разбор ошибок
```
Запусти обе версии промпта на data/golden.csv (src/run_agent.py), затем src/evaluate.py для каждой и src/compare.py.
Добавь строки в PROMPT_LOG.md. Затем прочитай results/errors_*.csv и предложи категорию причины
(data / prompt / guideline / model) для каждой ошибки в отдельной колонке cause_suggested. Мою колонку cause не трогай.
Выведи топ-3 причины по частоте и 1 гипотезу правки промпта на каждую.
```

## Промпт 6. Новая версия промпта
```
Гипотеза: <напишите>. Создай prompts/prompt_v3.txt на основе v2 с минимальной правкой под эту гипотезу.
Примеры для few-shot придумай новые, НЕ из data/golden.csv. Прогони, сравни с v2 через compare.py, обнови PROMPT_LOG.md.
Если разница не значима, так и скажи.
```
