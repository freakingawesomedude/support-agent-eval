# Инструкция по разметке golden set (v1.0)

Версия: 1.0. Любое изменение правил = новая версия + запись в конце файла.

## 1. Цель
Для каждого обращения клиента определить:
- `category` - тема обращения (одна из 5)
- `escalate` - нужно ли передать обращение живому оператору (`true` / `false`)

Размечайте так, как должен поступить **идеальный оператор**, а не так, как отвечает модель.

## 2. Категории
| category | Что входит | Примеры |
|---|---|---|
| payment | списания, двойное списание, счета, способы оплаты, неудачная оплата | "I was charged twice" |
| delivery | статус заказа, трекинг, задержка, потеря посылки, адрес доставки, способы доставки | "Where is my parcel?" |
| refund | возврат денег, возврат товара, отмена заказа, комиссия за отмену | "I want my money back" |
| tech_issue | ошибки сайта/приложения, вход, регистрация, пароль, доступ к аккаунту | "I can't log in" |
| other | отзыв, общий вопрос, контакты, подписка, пустое/бессмысленное сообщение | "What are your opening hours?" |

## 3. Escalate = true, если есть ХОТЯ БЫ ОДИН признак
1. Мошенничество, несанкционированные списания, взлом или кража аккаунта
2. Юридические угрозы: адвокат, суд, регулятор, chargeback
3. Клиент явно просит человека, менеджера, оператора
4. Угроза безопасности или здоровью
5. Сильное раздражение И проблема уже поднималась ранее без результата

Во всех остальных случаях `false`. Признак эскалации не зависит от категории.

## 4. Правила для спорных случаев
| Ситуация | Решение |
|---|---|
| Две темы в одном обращении | Категория основной просьбы (о чём клиент пишет первым и что просит решить). Если не ясно: payment > refund > delivery > tech_issue > other |
| Пустое сообщение, бессмыслица, "asdf" | category=other, escalate=false (бот просит уточнить) |
| Грубость без юридических угроз и без повторного обращения | escalate=false |
| Просьба "соедините с оператором" в вежливой форме | escalate=true (п. 3) |
| Сообщение не на английском | Размечайте по смыслу; помечайте `type=edge` |
| Вопрос про оформление нового заказа или изменение заказа | delivery (допущение v1.0, зафиксировано) |
| Сомневаетесь между двумя категориями | Выберите по правилу выше, в `comment` напишите "спорно: A/B" |

## 5. Колонки golden.csv
`id, text, source, category, escalate, type, comment`
- `source`: bitext / handwritten / llm_draft
- `type`: typical / rare / edge / negative / noisy
- `negative`: случаи, где правильный ответ - НЕ эскалировать, хотя текст эмоциональный

## 6. Состав набора (цель 150-200)
- ~60% typical (из Bitext, по ~10 на исходную категорию)
- ~15% edge (две темы, двусмысленные)
- ~10% rare (мошенничество, юридические угрозы, угроза безопасности)
- ~10% negative (эмоционально, но без эскалации)
- ~5% noisy (опечатки, пустые, мусор)
Доля escalate=true должна быть 15-30%, иначе precision/recall бессмысленны.

## 7. Процесс
1. Разметьте сами, не глядя на подсказки модели.
2. Через 3+ дня перемаркируйте 30 случайных строк (без просмотра старых меток).
3. Посчитайте kappa: `python src/kappa.py data/golden.csv data/relabel.csv`.
4. Расхождения -> уточните правила -> поднимите версию инструкции.
5. Golden set не копируйте в промпты и few-shot.
